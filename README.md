# 花生片 Peanup

花生片 Peanup 是一款正在打磨中的 3.68 英寸 E6 六色墨水屏产品，像素密度约为 258.7 PPI。

本仓库包含面向 Kickstarter 的多语言产品预览站、公开产品文档和工程说明。网站不提供预售或预约，也不把众筹目标参数写成已经量产验证的事实。

网站：[pean.caiths.com](https://pean.caiths.com) · 联系：[i@caiths.com](mailto:i@caiths.com)

继续设计或修改页面前，请先阅读 [DESIGN_HANDOFF.md](./DESIGN_HANDOFF.md)。

## 产品口径

- 3.68 英寸 E6 六色墨水屏，约 258.7 PPI。
- 通过 Bluetooth Low Energy 近场传图，画面刷新后由电子纸保持。
- 3 mm、28 g 和 1 个月以上续航是众筹目标规格；续航取决于刷新频率。
- 整机无外露接口，使用 Qi 无线充电。
- 内置磁环，兼容磁吸摆放和 MagSafe 磁吸配件；不暗示未经确认的 Apple 认证。
- iOS App 以 Apple 生态为主，支持快捷指令；另提供微信小程序传图路径和后续第三方接入空间。
- CUID NFC 仅在门禁系统支持、获得授权并符合当地规则时可用。

## 实现重点

- Astro + TypeScript 静态输出，不使用服务端运行时、React 或 i18next。
- 三幕自然场景保留原有 p5 绘图语义，但由项目内 `miniP5.ts` 提供所需的轻量 Canvas API，不加载完整 p5 包；第四幕在线体验使用原生 Canvas。所有动画只存在于产品的电子纸有效区，12 种本地雨滴轮廓合并为一张透明 WebP 图集，只产生一次素材请求。
- 四幕 HTML 内置零额外请求的六色云层静态首帧。微信等慢速 WebView 会先看到完整电子纸画面，异步 Canvas 就绪后用透明度接管，不改变舞台尺寸，也不出现空白占位。
- 四幕内部绘制统一使用厂家面板的 `528 × 792` 像素矩阵；外层舞台沿用线上版本更适合观看的 `3:4` 展示比例，桌面约 `510 × 680px`、移动端约 `315 × 420px`。网页比例不代表 3.68 英寸实体大小。
- 四幕的雨滴、花枝生长、飞燕与写屏都由用户滚动或点击直接驱动，不会因为 Arc、微信 WebView 或系统误报“减少动态”而整幕消失。系统减少动态仍会停掉枝条的闲置摇摆；离开舞台和页面切后台时 Canvas 继续暂停，因此不会变成持续播放的背景动画。
- 六色云雨、5 条花枝与花瓶、30 只飞燕和琴弦波动共享同一套 880ms 自下向上写屏过渡；其中 10 只飞燕会停在谱线附近，拨动或拖过屏幕会触发约 900ms 的琴弦余波。
- `01–03` 切换时缓存旧 Canvas 帧；进入或离开 `04` 时保留在线工作区 DOM，并用同一写屏进度裁切。四幕使用原生 Tab 语义与单一焦点，支持点击、触摸、方向键、Home 和 End；切换会立即锁定目标幕再平滑移动页面，避免途中误触发其他幕。照片和文字输入始终同时可见，工具栏在写屏结束后出现；120 字以内文本会在 528 × 792 画布内自动换行与缩放。
- 手机端四个场景 Tab 使用统一的 `68px` 轨道与明确行高，容纳英文、德文和法文的两行标题；选中蓝线不会裁掉文字，也不会改变下方电子纸舞台尺寸。
- Canvas 在滚动、切幕和短时场景动画期间按需绘制，离开视口或页面隐藏时暂停。
- 六个电子纸颜料样本是静态 Canvas，不响应悬浮、不缩放、不加滤镜或阴影。纹理模块与抖动算法模块分开按需加载；桌面六个 backing store 合计约 `0.09 MiB`，手机约 `0.06 MiB`，不请求六张额外图片。
- 技术章节的 Ordered、Floyd–Steinberg 与感知量化使用原生按钮语义。点击或键盘选择后会同步重算上方“六色成像”主预览、更新算法标签并播放一次短写屏；默认仍使用 Floyd–Steinberg。算法代码只在技术章接近视口时加载，不进入首屏关键路径。异步算法接管前复用同一张源图显示静态首帧，Canvas 完成首轮处理后再淡入，因此快速滚动和慢速 WebView 不会露出空白面板，也不会增加一张独立占位图请求。
- 技术章节顶部提供 `图像处理 / 六色算法 / 硬件能力 / 目标规格` 四段轻量索引，让长章节可以直接定位；索引只使用锚点和 CSS，不增加运行时脚本。
- 照片、日历、天气和书摘的模式演示之后保留一条开放式省略号轨道，明确四种内容只是示例，不是显示上限。对应六语文案位于 `ProductCopy.content.more`，中英文产品 FAQ 同步说明最终能由 App、小程序或快捷指令生成的六色帧都可成为下一幅画面，但不提前承诺尚未开放的内容接口。
- iPhone 样板以 Apple 公布的 `71.9 × 150.0 × 8.75 mm` 机身、`6.3 英寸`显示器与 `1206 × 2622` 像素比例（逻辑尺寸 `402 × 874 pt`）为依据。页面不加载远程组件、React 或机模运行时；本地裁剪后的 `662 × 1380` 轻量 PNG 只负责钛金属边、R 角、按键和机身细节，容器同时保持源图 `662 / 1380` 比例，避免透明画布的横向留白把边框拉宽。屏幕内容层按透明抗锯齿边缘做视觉校准，使用 `x=28..634 / y=35..1345`，即 `left 4.2% / top 2.53623% / width 91.6% / height 94.92754%`；玻璃开口使用 `13.8% 13.8% 9.35% 9.35% / 4.85% 4.85% 3.2% 3.2%` 的不对称圆角，分别贴合上弧和下弧；机框图片使用原生 `contain`，不做横向拉伸。状态栏完整使用 `402 × 62 pt` 坐标系的本地 `iphone-17-pro-status.png`（`1056 × 163 px`），整条透明画布向左平移约 `12pt`，把 `9:41`、蜂窝、Wi-Fi 和电池落在两侧约 `24pt` 安全区内，资源失败时才使用同坐标的 CSS 兜底。普通态由 CSS 覆盖层统一灵动岛胶囊和镜头高光，遮住源图中分离的镜头误差；传输状态在同一坐标上横向展开并显示 `68%` 写屏进度。机内根视图保持 `overflow: clip`，触摸表面保留 `pan-y`；不得恢复粗重自绘边框、安装图标包，或为了机模效果阻断页面滚动。
- `1592px` 以上的首屏、固定页头、规格带和装订线使用独立故事画框：左右至少保留 `76px`，最多扩展到 `1920px`；正文仍保持 `1440px` 阅读上限。这样带鱼屏不会只剩一条狭窄内容带，也不会把正文拉成难读的长行。
- Apple 生态不再把所有信息挤在一张静态手机图里。桌面端让手机和四步轨道并排；平板与手机把“本地整理 / 内容架 / 快捷指令 / 传输进度”改成模型上方的横向状态条，点击时不用滚回屏外寻找手机。桌面机模宽度收敛在 `288–328px`，平板收敛到 `304px` 上限，手机为 `62vw / 238px` 上限，始终保留完整 71.9:150 轮廓。内容架复用现有照片、日历、天气和书摘数据，在手机内生成四幅本地界面，不增加图片请求。手机同步切换真实界面并播放一次短写屏扫描；进入传输状态时灵动岛同步展开并显示进度，离开后恢复紧凑状态。四个控制项与四个手机界面使用完整 `tab / tabpanel / aria-labelledby` 语义，当前状态通过 `aria-live="polite"` 播报。下方 07:30、12:40、18:30 与 22:30 时间轨道继续演示天气、照片、一日总结和书摘四种更新时刻。两组控件均支持点击与键盘，纵向触摸滚动不被模型截获。该交互由 `phoneShowcase.ts` 接近视口时加载；中英文兼容文档使用同一组四步说明串起本地处理、内容选择、快捷指令与传输反馈。
- 硬件能力卡使用四个本地 SVG 图标；正面纯白、背面 `#ecece8`，支持悬浮、点击、键盘、`Esc` 收起和减少动态模式。手机端固定为紧凑 `2 × 2`，在 `360px` 下仍完整容纳六种语言的翻转正文；产品页公开 `#hardware` 与 `#specifications` 锚点，兼容文档可以直接回到对应章节。
- 规格章在十二项规格之后使用三段开放式证据轨道，依次区分“厂家面板规格 / Kickstarter 目标 / 开放支持前公布”。三段分别深链产品指南规格、众筹目标和支持前清单；桌面为细线三列，手机转为纵向轨道，不使用状态徽章或卡片墙。六种语言的链接顺序由 `scripts/verify-site.mjs` 强制校验。
- 亮色与暗色共享同一套编辑画册主题；圆形日月开关跟随系统偏好并记住手动选择。支持 View Transition 的浏览器会从开关位置用 500ms 圆形页面快照揭幕，让背景、文字和首图沿同一边界切换，不再出现圆外白字叠白底；旧 WebView 使用 320ms 同步颜色渐变。1.4 KB 的对应主题首图预览会立即同步显隐，高清图片解码后再无跳动接管，因此弱网下不会先卡住按钮。主题切换是一次明确的用户操作；浏览器报告 `prefers-reduced-motion` 时仍保留不遮挡正文的 340ms 紧凑揭幕，其余闲置动效继续遵守减少动态偏好。

## 本地开发

需要 Node.js 20 或更高版本，仓库使用 pnpm lockfile。

```bash
pnpm install --frozen-lockfile
pnpm dev
```

质量检查与生产构建：

```bash
pnpm check
pnpm build
pnpm verify:site
git diff --check
```

`pnpm build` 已在 Astro 检查与静态构建后自动执行 `verify:site`；单独运行该命令可以复核 32 个 HTML 路由、内部链接、锚点、canonical、hreflang、JSON-LD 类型、FAQPage 内容、TechArticle 日期、sitemap 以及生产包中的无关 Finder 元数据。校验器还锁定四幕 Tab 顺序、六色静态首帧、第四幕文件类型与 120 字约束、重置和隐私提示、全部图片 `draggable="false"`、零外部脚本/图片/样式请求、404 的透明抠图资产，以及双语支持页的复制控件和联系入口。静态产物位于 `dist/`，可部署到 Vercel、Cloudflare Pages 或任意 Nginx 静态站点。Astro 配置不依赖静态 Vercel adapter。

## 图片保护边界

所有展示图片通过 CSS 禁止选择、浏览器拖拽与触摸长按呼出，并在 HTML 中使用 `draggable="false"`。所有页面共享的轻量脚本只对 `img`、`picture` 或 `.protected-media` 内的事件阻止拖拽和右键菜单，不影响正文和普通链接。页面使用 `noimageindex` 与 `max-image-preview:none`；Vercel 或生产 Nginx 需要为 `/assets/*` 增加 `X-Robots-Tag`，GitHub Actions 会检查产品图响应头。社交分享使用单独的低分辨率品牌图。

这些措施用于减少误操作和遵守规则的搜索引擎图片曝光，不是 DRM，也不能保证所有爬虫遵守指令。公开网页无法真正阻止访客从 Network、缓存、源码或截图取得已经传输到浏览器的素材。因此仓库只应保存网页展示尺寸资源，不应加入摄影原片，也不使用 Base64 或全站禁右键伪装成下载保护。

## 发布

推送到 `main` 后，GitHub Actions 会执行 Astro 检查和静态构建，再上传 `dist/` 并原子切换 `/www/wwwroot/pean.caiths.com/current`。切换前记录旧链接，切换后校验 release 与 `current`，并重试验收公网 HTTPS、Docs、404、索引文件、HTTP 跳转和图片响应头。激活后的检查失败时，仅当上一版本仍存在且 `current` 仍指向本次失败 release，工作流才原子恢复旧链接；没有上一版本时需要人工处理。只在验收成功后保留最新五个 release。

GitHub `production` Environment 需要 `DEPLOY_HOST`、`DEPLOY_USER`、`DEPLOY_SSH_KEY` 和可选的 `DEPLOY_PORT` Secrets。Nginx 站点根目录必须指向 `/www/wwwroot/pean.caiths.com/current`；这是纯静态站点，不应反向代理到 Astro 开发端口。修改宝塔 Nginx 配置后先执行 `nginx -t`，通过后再 reload。

Cloudflare 凭据、服务器密码、私钥和其他密钥不得写入仓库或文档。DNS 中的 `pean` 记录应指向实际承载该静态目录的源站，并根据 Cloudflare SSL 模式配置对应的源站证书。

完整的宝塔 / Nginx、TLS、验收和回滚说明见 [docs/DEPLOYMENT.md](./docs/DEPLOYMENT.md)。
